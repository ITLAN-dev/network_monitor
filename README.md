# Network Monitor - TIME_WAIT и сетевая нагрузка

Мониторинг TCP-соединений в состоянии `TIME_WAIT` и сетевой нагрузки в реальном времени. Помогает диагностировать проблемы с исчерпанием портов, переполнением буферов сети и DDoS-подобными нагрузками.
---

## 🚀 Возможности

- ✅ Мониторинг количества соединений в состоянии `TIME_WAIT`
- ✅ Отслеживание скорости сети (отправка/получение в Мбит/с)
- ✅ Подсчет пакетов в секунду (PPS)
- ✅ Обнаружение ошибок сети и потерянных пакетов
- ✅ Пороговые предупреждения (настраиваемые)
- ✅ Показ ТОП-5 удаленных хостов, создающих `TIME_WAIT`
- ✅ Отображение использования динамических портов
- ✅ Два режима работы: тихий и вербозный
- ✅ Сохранение логов в файл
- ✅ Работает на Windows (Python 3.6+)

---

## 📦 Установка

### 1. Установите Python

Скачайте и установите Python 3.6+ с официального сайта:  
👉 [python.org/downloads/windows/](https://www.python.org/downloads/windows/)

**Важно:** При установке обязательно поставьте галку **"Add Python to PATH"**.

Проверьте установку:
```
python --version
```
2. Установите зависимость
```

python -m pip install psutil
```
3. Скачайте скрипт

Сохраните код скрипта как `network_monitor.py` в удобную папку.

Быстрый старт

Базовый запуск (тихий режим)
```
python network_monitor.py
```
Для гигабитной сети с настраиваемыми порогами
```
python network_monitor.py -t 1500 -w 800 -n 950 -nw 700
```
Вербозный режим (видно всё)
```
python network_monitor.py -v
```
⚙️ Флаги и параметры
Основные флаги
```
-t	--threshold	1000	Критический порог TIME_WAIT
-w	--warning	500	Предупредительный порог TIME_WAIT
-n	--network-threshold	900	Критическая скорость сети (Мбит/с)
-nw	--network-warning	700	Предупредительная скорость сети (Мбит/с)
-i	--interval	1.0	Интервал проверки в секундах
-l	--log-file	None	Путь к файлу для сохранения лога
-v	--verbose	False	Вербозный режим (показывать всё)
-q	--quiet	False	Максимально тихий режим
-h	--help	-	Показать справку
```
📊 Режимы работы
1. Тихий режим (по умолчанию)

Показывает только предупреждения, ошибки и краткий статус каждые 10 секунд.
```
python network_monitor.py
```
2. Вербозный режим

Показывает каждую проверку с полной статистикой.
```
python network_monitor.py -v
```
3. Максимально тихий режим

Показывает только критические ошибки.
```
python network_monitor.py -q
```

4. С записью в файл

Все выводы дублируются в указанный файл.
```
python network_monitor.py -l monitor.log
```

📝 Примеры использования
Для гигабитной сети (рекомендуемые настройки)
```
python network_monitor.py -t 1500 -w 800 -n 950 -nw 700
```

Вербозный режим с сохранением в файл
```
python network_monitor.py -v -l full_log.txt -t 1500 -w 800 -n 950 -nw 700
```

Только ошибки в лог
```
python network_monitor.py -q -l errors.log -t 1500 -w 800
```

Проверка каждые 2 секунды
```
python network_monitor.py -i 2 -t 1500 -w 800
```

Показать справку
```
python network_monitor.py -h
```

📈 Метрики
```
TIME_WAIT	Количество соединений в ожидании закрытия	Всегда
Отправка	Скорость исходящего трафика (Мбит/с)	Всегда
Получение	Скорость входящего трафика (Мбит/с)	Всегда
PPS	Пакетов в секунду	Всегда
❌ Ошибки сети	Ошибки на уровне драйвера/сетевой карты	Только при проблемах
📦 Потерянные пакеты	Пакеты отброшены из-за переполнения буфера	Только при проблемах
ТОП-5 хостов	Адреса, создающие больше всего TIME_WAIT	При предупреждениях
Использование портов	% использования динамических портов	При критических значениях
```

🔍 Диагностика проблем
Какие проблемы помогает выявить:
```
Исчерпание портов	TIME_WAIT > 1500, "Использование портов: 95%"
Переполнение буфера D-Link	Рост ошибок и потерь при высокой скорости
Утечка сокетов в приложении	Постоянный рост TIME_WAIT без снижения
DDoS-атака	ТОП-5 хостов показывает один IP с тысячами соединений
Проблемы с сетевым кабелем	Рост ошибок сети без потери скорости
Что делать при обнаружении:

    TIME_WAIT > 1000: Проверьте код приложения на утечку сокетов

    Ошибки и потери: Проверьте сетевой кабель, порт коммутатора

    Высокая скорость > 700 Мбит/с: Возможно, коммутатор не справляется (D-Link)

    Один хост создает много TIME_WAIT: Возможно, DDoS или проблема с конкретным сервисом
```
